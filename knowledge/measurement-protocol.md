# 量測協議：在這台機器上，什麼數字才算數

這份檔案定義**如何量**，不放實驗數據。數據在 [experiment-log.md](experiment-log.md)。

這些規則不是通則，是從這個 repo 在這台機器（Apple M3 / 16GB）上的實際失敗推出來的。
違反過兩次，兩次都得出錯誤結論並據此排錯了工作優先序。

---

## 1. 跨次量測相減，結果無效

同一份工作在這台機器上的每步成本，觀測到在 **4.8 到 12.9 ms 之間漂移**（2.7 倍）。
主因是 MPS 與視窗伺服器（SkyLight）及 Claude app 共用 GPU，而 UI 負載會隨工作階段變化。

因此：

- **禁止**用「A 條件某次跑的秒數」減去「B 條件另一次跑的秒數」來歸因成本。
- 這種相減產生過兩個錯誤結論，見 log 中的 EXP-009 與 EXP-011。

## 2. 配對交錯才能比較

要比較兩個條件，必須在**同一個行程內交替執行**，取配對差分：

```
for i in range(N):
    a = measure(condition_A)
    b = measure(condition_B)
    diffs.append(a - b)
```

判定門檻：`|mean| > 2 * stderr`。不到就寫「無法解析」，**不寫成改善**。

參考實例：EXP-009（t=10.5，解析成功）對比 EXP-012（t=0.04，40 對後仍無差異）。

## 3. 先量噪音下限，再看效果

任何效能或指標宣稱，都要先知道「同一設定重複跑的散布」。

- 效能：同設定至少重複 3 次，報 median 與 range。
- 模擬指標：Poisson 輸入**未設 seed**，單次跑不構成一個率。
  參考值重複平均（`calibrate_w_syn.py --reference-repeats`），
  並用 `--noise N` 量散布。實測 MN9 發放率的散布是 sd 約 2%、跨次 range 約 6%。

擬合出來的位移若小於參考值自身散布，結論是「**不需要可量測的變更**」，
不是「變更了 X%」。EXP-008 的 `signs` 模式是這個情況：兩次獨立擬合得到
0.2653 與 0.2802，跨在論文值 0.275 兩側。

## 4. 效能宣稱必須附帶活動量

事件驅動傳播的成本隨發放數變化，稀疏矩陣乘則不隨活動量改變。
因此「快 N 倍」這種說法**沒有活動量就沒有意義**。

報告時一律附上：每步發放數，或換算成每神經元平均 Hz。
見 EXP-013 的交叉點。

## 5. 正確性與效能分開驗證

效能量測不能證明正確性。數值等價要用**固定重播輸入**（排除 RNG）逐位元比對：

- 預先產生一串 Poisson 輸入，兩個條件餵同一串。
- 比對完整 spike raster 與最終膜電位，不只比總數。
- 通過標準：0 個不符項目、0 mV 差異。

範例腳本結構見 EXP-004、EXP-010 的 artifact 欄位。

## 6. 模型本身的量測陷阱

- **不反應期不限制發放率**。`refrac` 只閘控突觸輸入；Poisson 刺激直接加在膜電位上，
  繞過該閘。所以被直接驅動的神經元可以每個時間步都發放，
  實測達到不反應期理論上限的 1100%。
- **Poisson 驅動上限 10,000 Hz**。機率 = `rate * dt/1000`，超過 10,000 Hz 時 `p > 1`，
  `torch.bernoulli` 直接報錯。
- **`exc_indices` 會把指定神經元的不反應期設為 0**。把全腦傳進去等於關掉不反應期。
